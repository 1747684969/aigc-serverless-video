# 故障排查手册

这里记录的每一条都是**本项目真实踩过的坑**及其根因，不是从文档抄来的。

---

## 1. ⭐「未能解析视频文件」= 云端返回了 HTTP 200 + 空 body

**这是本项目最坑的一个故障，也是最有价值的一条经验。**

### 现象

本地 ComfyUI 报错：

```
未能解析视频文件: ...\input\modal_h3_45760653284804.mp4，请确保本地支持基本视频解码。
```

同时云端日志显示"出片成功"。

### 排查过程

1. 先怀疑本地解码能力 → 检查 ffmpeg 是否存在、换解码器 → **无改善**
2. 检查落盘文件 → **mp4 是 0 字节**
3. 回看 HTTP 响应 → **云端返回 200，但 body 为空**

### 根因

**云端函数返回了 HTTP 200 + 空 body**，本地把空字节写成了 0 字节 mp4。
0 字节文件任何解码器都打不开，所以报错信息**完全指向了错误的方向**——它让人以为是本地解码问题。

可能原因：Modal 冷启动超时、服务端异常但仍返回 200、或接口参数/轮询方式不匹配。

### 修复

| 层 | 修复动作 |
|---|---|
| **本地节点** | 新增 `_looks_like_video()` 魔数校验 + 空响应检测；对空响应重试 3 次；报错信息明确指向"云端返回空内容，而非本地解码问题" |
| **云端端点** | 所有异常统一返回 JSON 错误 + 非 200 状态码，让失败**可自解释** |
| **解码链** | 加三级兜底：PyAV → OpenCV → ffmpeg，全部失败才报错并附各层详情 |

### 经验

> **不要相信错误信息的字面含义。** "本地解码失败"的真实根因可能在网络另一端的响应体里。
> 判据是：**先看文件大小，再看 HTTP body，最后才怀疑解码器。**

## 2. `Node 'VHS_VideoCombine' not found`（HTTP 400）

### 现象

```
云端生成失败: HTTP 500 - {"error":"提交工作流失败: HTTP 400 -
{"error": {"type": "missing_node_type",
"message": "Node 'VHS_VideoCombine' not found. The custom node may not be installed."}}"}
```

### 根因

云端 ComfyUI 版本的**核心节点已内置出片能力**，而自定义节点 `VHS_VideoCombine` 是否可用取决于插件安装情况与版本。

### 修复

提交前先请求 `/object_info` **动态探测可用节点**：

- 有 `CreateVideo` + `SaveVideo` → 走核心节点（首选）
- 否则回退 `VHS_VideoCombine`（VHS 插件）
- 两者都无 → 明确报错

### 经验

云端 ComfyUI 是**运行时拉取最新代码**的，节点集合会随上游变化。
**不要硬编码节点名**，用 `/object_info` 探测。

## 3. Turbo LoRA 缺失导致静默回退到 20 步

### 现象

出片正常，但耗时约为预期的 2.5 倍，成本翻倍。

### 根因

Turbo LoRA 未下载进 Volume，端点检测不到 LoRA 文件，**静默回退到标准 20 步**。

### 修复

- 端点检测到 `turbo_mode=True` 但无 LoRA 时**打印显式警告**，不再静默；
- 把 LoRA 纳入 `download_models.py` 的下载清单（注意它在另一个 HF 仓库里）。

### 经验

**性能参数的静默回退是最贵的 bug**——功能看起来正常，钱在悄悄烧。

## 4. 系统代理抽风导致请求中断

### 现象

出片请求偶发失败，报 `ProxyError`。

### 根因

本机运行时挂着 v2rayN / Clash 类代理，代理进程重启或端口切换时请求被拒。

### 修复

`_post_to_cloud()` 捕获 `ProxyError` → 用 `session.trust_env = False` **自动改直连重试**。

### 经验

长耗时的 GPU 请求（几分钟到 20 分钟）**极易被本地网络栈打断**，
客户端必须对代理异常做显式处理，否则会浪费已经付费的云端算力。

---

## 5. 客户端超时 < 云端超时 → 丢掉已付费的结果

### 根因

云端函数 `timeout=1200`，若客户端超时设得更短，会出现：
**服务端算完了，客户端已经放弃** —— 钱花了，结果没拿到。

### 修复

客户端 `CLOUD_TIMEOUT = 1500` **必须大于**云端 `timeout = 1200`。

### 经验

分布式调用的超时设置要**成对设计**：客户端 > 服务端。

## 6. 画布尺寸不符合模型原生约束

### 现象

画面异常/运动不自然，或分辨率被莫名改变。

### 根因

MiniMax H3 的训练约束：

- 宽高必须是 **32 的倍数**；
- 短边有上限（原生档 16:9 = **1280×736**，约 0.9MP）；
- 帧数按 **17k+5 网格**吸附（5 秒 → 124 帧）。

### 修复

`_native_canvas()`：自动对齐 32 倍数、小画布提升到原生档位、短边收敛到上限，并打印调整说明。

**反面案例（不要做）**：

| 做法 | 问题 |
|---|---|
| 8fps 生成 22 帧凑"1 秒" | 帧间运动按 24fps 烘焙，2/3 运动从未生成 → 拖滞卡顿；且 22 帧远低于训练下限 ~124 帧 |
| 生成后抽帧到 8 帧播放 | 跳帧，动作不连贯 |
| 请求 8 帧（网格外） | 被吸附到 22 帧 |

想要慢动作的正确路径：**正常 24fps 生成 → RIFE 补帧到 48/60fps → 降速播放**。

## 7. 本地解码内存峰值过高

### 现象

本地解码成片为 IMAGE 张量时内存占用大，4GB 显存机器压力明显。

### 修复

- PyAV 解码改为**预分配 float32 数组逐帧写入**（容量不足时翻倍），避免"列表 + 整体转换"的双份峰值；
- `buf[n] /= 255.0` 用 **in-place** 运算，避免额外数组。

### 经验

峰值内存降低约 **30–50%**。

## 8. 冷启动慢（3–6 分钟读 26GB）

### 根因

模型放在网络挂载的 Modal Volume 上，每次冷启动都要读满 26GB。

### 缓解

- 提高容器复用率（`scaledown_window` 调大）；
- 镜像里固定 ComfyUI commit（`git checkout <sha>`），让 pip 层命中 Modal 构建缓存，省部署时间。

### 彻底解决

需常驻容器（成本高）或本地推理（显存不够）——**这是当前架构的固有代价**。

## 快速排障决策树

```
出片失败
├─ 本地报"未能解析视频文件"
│   └─ 先看文件大小 → 0 字节 → 查云端 HTTP body 是否为空（见 §1）
├─ HTTP 400 missing_node_type
│   └─ 云端 ComfyUI 节点集合变了 → 用 /object_info 动态探测（见 §2）
├─ 耗时/成本明显偏高
│   └─ 检查 Turbo LoRA 是否真的加载了（见 §3）
├─ ProxyError / 请求中断
│   └─ 代理问题 → trust_env=False 直连重试（见 §4）
├─ 云端算完但拿不到结果
│   └─ 客户端超时是否小于云端超时（见 §5）
└─ 画面异常 / 分辨率被改
    └─ 画布与帧数是否符合模型原生约束（见 §6）
```
